# ANANISIM OS — раздел NOD (файловый мост)

## Архитектура

Агент X — лёгкий роутер без харнессов, без tool-calls, без циклов планирования.
Взаимодействие с NOD идёт через файловый мост (File-based IPC):

```
nod_bridge/
  task.json     → запрос от Агента X к NOD
  result.json   → ответ от NOD обратно к Агенту X
```

### Формат task.json

```json
{
  "id": "<uuid>",
  "task": "<текст запроса>",
  "timestamp": "YYYY-MM-DD HH:MM:SS"
}
```

### Формат result.json (ожидается от NOD)

```json
{
  "status": "ok",
  "message": "<ответ NOD>"
}
```

или при ошибке:

```json
{
  "status": "error",
  "message": "<описание ошибки>"
}
```

## Маршрут API

`POST /api/chat` с телом `{"query": "...", "agent": "x"}`

- Если в запросе есть веб-триггеры (`сайт`, `браузер`, `проверь`, `найди`, `остатки`, `api` и т.п.) — задача отправляется в NOD через файловый мост.
- Если триггеров нет — возвращается `{"status": "skip"}`.
- Таймаут ожидания результата от NOD: 120 секунд.

## Как запустить монитор NOD

```bash
python backend/nod_monitor.py
```

> Путь именно `backend/nod_monitor.py` — папка `tools/` в `.gitignore` и в свежем клоне её нет.

Монитор следит за `nod_bridge/task.json`. При появлении задачи выводит в консоль:

```
[NOD] Новая задача: <текст>. Скопируйте в чат NOD
```

Если найден CLI NOD (`nod run` в PATH), монитор запустит его автоматически. Иначе задачу нужно скопировать в чат NOD вручную, а результат NOD должен быть записан в `nod_bridge/result.json`.

## Куда копировать результат

После обработки задачи в чате NOD, результат должен быть записан в файл:

```
nod_bridge/result.json
```

Агент X прочитает этот файл, удалит оба файла (`task.json` и `result.json`) и вернёт ответ через API `/api/chat`.

Если результат не появится за 120 секунд — вернётся `{"status": "timeout", "message": "NOD не ответил. Проверьте приложение."}`.

## Ограничения

- Не трогать Дрона и Джинни — только Агент X и файловый мост.
- Никаких HTTP-запросов к NOD — только файлы в `nod_bridge/`.
- Таймаут ожидания: 120 сек.

## Публикация кабины в интернет (ngrok)

Домен `dronxgenie.com` зарегистрирован через PDR/Privacy Protect, поэтому смена NS-серверов на Cloudflare невозможна.
Кабина публикуется через **ngrok** — публичный HTTPS-туннель без прав на DNS.

### Запуск туннеля

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup_tunnel.ps1
```

Скрипт:
1. Установит `ngrok` через `winget` (если не установлен).
2. Запустит туннель на `http://localhost:5173`.
3. Выведет публичный URL вида `https://xxxx.ngrok-free.app`.

### Перед запуском

Vite dev-сервер должен быть запущен в отдельном окне:
```powershell
cd frontend
npm run dev
```

Затем откройте публичный URL из вывода скрипта — лендинг, PIN-защита и кабина будут доступны из любой точки мира.

### Остановка туннеля

```powershell
Stop-Process -Id $(Get-Content $env:TEMP\dronxgenie-ngrok.pid)
```

## Безопасность (правила репозитория)

- **`.env` и `backend/data/.vault_password` / `backend/data/nod_vault.json` никогда не коммитятся** — они в `.gitignore`.
- `.env.example` — только плейсхолдеры, реальных ключей там быть не должно.
- Мастер-пароль хранилища читается из переменной `NOD_VAULT_PASSWORD` либо из `backend/data/.vault_password` (локально).
- Если секрет всё же попал в git — удалять из HEAD недостаточно: нужна ротация ключа у поставщика и перезапись истории (`git filter-repo` + `push --force`).
